## 1. Размещение префаба В СВОЁМ мире (аддон не содержит мира!)

Аддон **не создаёт и не меняет миры/слои/сценарии/спавны** — это явное
требование владельца. Префаб ставишь в свой существующий мир сам.

Префабы (ResourceName / GUID):

| Вариант | ResourceName |
|---|---|
| MP-133 | `{FC1935AF936F63E5}Prefabs/Weapons/MP133_Lab/armst_Shotgun_mp_133_Lab.et` |
| MP-133 RIS | `{4B288C21B7125D50}Prefabs/Weapons/MP133_Lab/armst_Shotgun_mp_133_Ris_Lab.et` |

5. Убедись, что аддон `ARMST_MP133_AnimationLab` включён как зависимость сессии.
6. Поставь один из префабов в свой мир (World Editor или тот способ, которым ты
   обычно размещаешь оружие) и запусти сцену.
7. Возьми оружие и **проверь название в UI: «MP-133 [LAB]»** / «MP-133 RIS [LAB]».
   Вложи трубчатый магазин `12g 10rnd` стандартным способом (инвентарь).

## 2. Управление в тесте

| Действие | Клавиша |
|---|---|
| Дослать ОДИН патрон в трубу (добавить в трубчатый магазин) | **R** (нажми — досылает; цикл продолжается, пока труба не полна или резерв не пуст; нажми снова после выстрела) |
| Помповый цикл (дослать патрон в ствол / перезарядка после выстрела) | **LSHIFT+R** (существующее ARMST-действие) |
| Первичная зарядка (вложить трубчатый магазин) | Инвентарь: перетащить `12g 10rnd` в слот магазина |

Конфиг ввода не нужен (v2): для лабораторных дробовиков R перехватывается в
`OnApplyControls` и превращается в досылку; обычные дробовики не затронуты.

## 3. Проверки (отмечай результат напротив каждого шага)

### A. Базовое
- [ ] A1. Подъём/идл: корректная поза дробовика, без «рваных» поз.
- [ ] A2. Выстрел с патроном в трубе: анимация отдачи, патрон расходуется (счётчик трубы −1).
- [ ] A3. Выстрел с пустой трубой: щелчок, без выброса и без «придуманного» патрона.

### B. Помпа (LSHIFT+R)
- [ ] B1. После выстрела помпа двигает цевье; **ровно один** патрон переходит
      из трубы в ствол (труба −1 на каждый помповый цикл, без двойного списания).
- [ ] B2. Помпа с пустой трубой: патрубок чистый, счётчик не уходит в минус.

### C. Досылка патронов (R)
- [ ] C1. Начало: нажатие R → один цикл вставки, труба +1, резерв −1.
- [ ] C2. Цикл продолжается автоматически: каждые ~3,3 с труба +1, пока резерв/ёмкость позволяют (одиночное нажатие R, без удержания).
- [ ] C3. Труба «полна» (по умолчанию 2): циклы останавливаются, «призрачных» патронов нет.
- [ ] C4. Резерв 0: циклы останавливаются, патрон не добавляется.
- [ ] C5. Ёмкость: при необходимости поменяй на префабе `armst_Shotgun_mp_133_Lab.et`
      → `ARMST_MP133_Lab_Component` → `m_iTubeCapacityOverride` (0 = правило ARMST, т.е. 2).

### D. Прерывания
- [ ] D1. Выстрел/помпа во время досылки: чистое прерывание, никаких лишних патронов.
- [ ] D2. Опускание оружия / смена оружия / экипировка обратно: восстановление, нет залипших состояний.
- [ ] D3. Полный цикл «досылка → помпа в ствол → выстрел»: число патронов сходится
      (труба + ствол + резерв = константа на протяжении всех операций).
- [ ] D4. Нажатие R не должно запускать ванильную замену трубчатого магазина
      (труба не «выпадает»/не меняется) — ключевая проверка перехвата.

### E. Сетификация
- [ ] E1. В соло (клиент=сервер) счётчики совпадают с логами
      `[ARMST_MP133_LAB] Insert COMMIT: tube %1 -> %2, reserve %3`
      (включи `m_bLabDebugLog 1` на префабе).
- [ ] E2. Повторный/переигранный эвент не добавляет патрон дважды (cooldown 500 мс).

## 6. Диагностика (встроена, всегда включена)

Скрипты лаборатории пишут в лог два маркера — по ним видно всё состояние:

- `[ARMST_MP133_LAB]` — компонент оружия: баннер при спавне, `capacity`, `reserve`.
- `[ARMST_MP133_LAB-DIAG]` — контроллер персонажа:
  - `character component init: anim=… cmdReload=… isServer=…` — скрипт жив;
  - `OnControlledByPlayer controlled=… local=…`, `watcher started`;
  - `WEAPON wm=… wpn=… ent=… prefab=… labComp=… tube=…/… reloadType=… startReloading=… raised=… isReloading=…` — **безусловный лог текущего оружия (любого) раз в секунду** (V2): сразу видно, что в руках и найден ли lab-компонент;
  - `STATE labWeapon=1 cap=… tube=…/… chambered=…/… reserve=… clientInsert=… serverInsert=… armed=… isReloading=…` — снимок лаб-оружия;
    (раз в секунду, пока в руках лабораторное оружие — это главный снимок);
  - `anim event '<Name>' int=… t=… isServer=…` — **каждое** известное анимационное
    событие (`BlendIn/Out`, `Weapon_Rack_Bolt`, `Weapon_EnableFire`,
    `Weapon_SpawnMagazine`, `Weapon_AttachMagazine`, `Weapon_MagRelease`,
    `Weapon_DetachMagazine`, `Weapon_DespawnMagazine`, `ARMST_Lab_Shell_*`);
  - `watcher: reload request detected …`, `begin insert loop …` /
    `begin skipped: …`, `stop: …`, `SERVER begin insert window …`,
    `SERVER Insert COMMIT: tube … reserve …`, `SERVER Insert REJECTED …`.

Если в логе нет ни одной строки `[ARMST_MP133_LAB]`/`-DIAG` — значит в сессии
нет лабораторного оружия/скрипта (проверь имя оружия «MP 133 (LAB)» и что
открыт проект лаборатории).
