## 1. Evidence contract

- `OWNER-RUNTIME`: observed in the owner's supplied Workbench/game logs or explicitly described by the owner, not independently reproduced by this research.
- `PROJECT-SOURCE`: read from the published `Weapon_ARMA_X` branch and its lab sources or existing file-level audits.
- `OFFICIAL-DOC`: published Bohemia wiki, reference tables, API and maintained samples. These describe the public interface, **not proof of this particular installed build**.
- `INFERENCE`: proposed mechanism/solution, not a tested outcome.
- `UNRESOLVED` / `SOURCE-UNAVAILABLE`: explicitly retained gaps; no fabricated certainty.

**Version boundary:** the project research targeted *installed Enfusion 1.8.0.13*. Currently hosted public scripting API pages inspected during this research say **Generated by 1.13.2**; signatures and semantics must be checked against the owner's installed SDK before code edits. Never mix SDK versions silently. Online Wiki page crawl dates are not a substitute for engine/build-version verification.

**Authority:** actual local addon and owner Workbench evidence > approved current policy > fresh project source > generated catalog snapshot > historic report > external reference/inference. Source reports may be correct for the old experiment without representing current implementation.

### G3-B2 observed local boundary
[Owner runtime evidence](https://github.com/Dubelkrya/Weapon_ARMA_X/issues/34#issuecomment-5975205409) confirms **offline** physical target `2/3` initially, successful repeated `0→1→2→3` with actual carried donor decrement and +250/+1000ms persistence, full-at-3 rejection and in-flight busy rejection. [Current published lab magazine](../labs/ARMSTMP133T4B_InstalledMagProbe/Prefabs/Test/ARMST_T4B_G3B2_Tube3Mag.et) directly overrides the inherited magazine component `MaxAmmo 3` and `AmmoMapping {0 0 0}`. [WRITE-ON fixture](../labs/ARMSTMP133T4B_InstalledMagProbe/Prefabs/Test/ARMST_T4B_G3B2_InventoryWide_WriteOn_TestWeapon.et) binds its `MagazineTemplate` to that mag. No automatic progression from these facts to safe reload or multiplayer is permitted.

The **owner-reproduced remaining bug**: pressing R with empty tube or rapid double-R can cause whole-mag swap; a 10-cap donor becomes installed and G3-B2 correctly rejects `target-capacity-mismatch` ([Issue #34 repro](https://github.com/Dubelkrya/Weapon_ARMA_X/issues/34#issuecomment-5975348824)). The actual command IDs **per occurrence** still need passive runtime logging; current G4-A audit's state association is a mechanism-level deduction, not a frame-by-frame owner trace.

## 6. Explicit research gaps / stop rules

1. **Immediate G4-A:** one passive owner trace of empty single-R and nonempty rapid double-R recording graph command integer/float, before/after current-mag entity+component ID, chamber, inventory donor and native animation events. Never report a command value as observed until this trace exists.
2. **Native magazine admission:** no SDK/project-verified per-weapon field that makes `MagazineWell12g` permanently nonremovable while retaining normal pump and chamber; `MaxAmmo=3` is **not** such a field.
3. **Sanitized-clip solution:** promising lab-only architecture, but graph-level prevention of native attach without input-level suppression, preserved pump and repeated R, low-FPS interruption, multiplayer and network UI remain **UNVERIFIED**.
4. **G3-B2 safety:** two separate `SetAmmoCount` writes are not atomic. Guarding and +250/+1000ms readback reduce observed faults but are not a distributed transaction/rollback guarantee.
5. **Engine/API version:** check any new code against the installed API version and current Workbench assets; public 1.13.2 signatures are background references only.
6. **External sources:** collect actual current Chungus and Core files with version/GUID/commit provenance *only if the owner provides them or an authorized connector makes them accessible*. No speculative “source reviewed”.
7. **Source licensing:** link official docs and samples; do not bulk-import or copy third-party ANM, source scripts or media into `Weapon_ARMA_X` without license and provenance review.

**Read-only research conclusion:** retain working G3-B2 and physical 3-cap tube; determine native input-to-graph route with passive owner evidence; scope future G4-A to lab-only wiring; only then consider Chungus-inspired staged G4-B. **No production integration or G5/MP result is asserted.**
