# Прицелы оружия: идентичность, наследование и пристрелка

Инструкция по итогам сессий 12–13 октября 2026. Применять перед изменением родителей, SightsComponent, helpers и геометрии. Датированное состояние: [отчёт](../../reports/WEAPONS_SESSIONS_2026-10-12_13.md).

## Сначала доказать, что редактируется активный ресурс

1. Разрешить live addon через `agent/scripts/addon_path.py`; catalog — снимок, не текущая истина.
2. Записать путь, GUID из meta, полную цепочку родителей и точные ID компонентов. Проверить GUID также в vanilla resourceDatabase/pak: отсутствие совпадений среди распакованных meta не доказывает уникальность.
3. Одинаковый GUID с vanilla означает override ресурса, а не независимого потомка. Имя с `armst_` и другая строка родителя не меняют идентичность.
4. Отсутствие элементов массива в текстовом override не является доказательством их удаления из эффективного ресурса. Проверить состав в Workbench; использовать точные унаследованные instance ID, не создавать дубликаты.
5. Для независимого родителя создать новый ресурс штатным способом, дождаться регистрации Workbench и прочитать выданный GUID. Не изобретать GUID, не переписывать старые meta.

См. [официальное описание override/duplicate/inherit](https://community.bistudio.com/wiki/Arma_Reforger:Data_Modding_Basics).

## Родитель и собственная копия

- `_base` — родитель своей игровой копии только после проверки реальной ссылки; имя само по себе не доказательство.
- Если просят изменить только родителя, менять только ссылку. Сохранить модель, цевьё/приклад, attachment slots, магазин, magwell, IK, animation graph, звук, режимы огня и отдачу. Проверять эффективные различия до/после: новый родитель может изменить отсутствующие локально значения.
- Общий родитель из M16 не является нейтральной оружейной базой: он несёт настройки M16. Не распространять его без проверки на все модели/калибры.
- Одна точка владения калибровкой: в base либо осознанный override копии. Не оставлять случайно разные углы у base и копии.
- Проверять world instance: локальные component overrides могут перекрывать prefab. Сверять GUID выбранной сущности, а не только имя в Hierarchy.
- Для «только 100» требуется один эффективный SightRangeInfo на 100 и корректный default index; число блоков в исходнике недостаточно.

## Три независимых слоя

1. Геометрия: вершина мушки и рабочая видимая кромка прорези целика.
2. Helpers и prefab: eye/front/rear, оси, ориентации, offsets; учитываются суммарно.
3. Баллистика: направление вылета, боеприпас, скорость и падение на фактической дистанции.

Не скрывать ошибку геометрии баллистическим углом. Показание HUD «100 m» — выбранная настройка, не измеритель расстояния. Использовать подтверждённую дистанцию до мишени и группу попаданий. Не объявлять знак/величину поправки доказанными по одному скриншоту.

## Геометрия и перенос

- Импортировать свежий live FBX, не старый blend. Основывать измерения на LOD0; отдельно сообщать, какие остальные LOD не изменялись.
- Проверять преобразование координат: у исследованного SIG FBX X/forward Y/height Z, TXO Coords XZY. Не переносить это на другую модель без проверки.
- Выбирать рабочую видимую кромку прорези, не произвольную верхнюю вершину или helper. Проверять ADS-вид визуально: числовое равенство неверно выбранных точек не является успехом.
- Перемещать доказанно выбранную сборку, сохранять остальную геометрию; синхронно править соответствующие TXO-вершины и необходимые helpers.
- Измерять также lateral alignment и ориентации chamber/muzzle. Вектор между ними не считать автоматически доказанным направлением вылета движка.
- До переноса: backup, SHA-256 исходников/meta, ограниченный diff, roundtrip экспорта. После: readback hash, число изменённых вершин, контроль нетронутых частей и meta.
- Перенос FBX/TXO не равен импорту XOB. Запуск Workbench не равен компиляции. Проверить результат импорта, бинарный ресурс и новую игровую сессию.

## Если две поправки подряд визуально не работают

Остановить подбор чисел. Проверить активный addon и GUID/override, base против копии, instance overrides, источник модели и актуальность XOB. Не повторять объяснение «кэш» после полного перезапуска без новых доказательств.

Отчёт всегда разделяет: статически подготовлено → установлено → подтверждено UI → импорт подтверждён → геометрия и пристрелка подтверждены в игре. Для каждого этапа нужны собственные доказательства. Непроверенные углы помечать provisional; не переносить их на все оружия.
